# ADR 0020 — 虚拟滚动：1w+ 素材量必做

**状态：Accepted** · 2026-08-08

## 背景

用户现有 1w+ 张照片，系统从第一天就要处理万级素材量。普通瀑布流全量渲染 DOM 会卡死。

## 决策

### 必须做虚拟滚动
- 瀑布流只渲染可视区域 + 上下缓冲区的图片卡片
- 不可见区域的 DOM 回收，只保留数据
- 滚动时动态创建/销毁卡片

### 技术选型
- 方案：`@tanstack/react-virtual`（轻量、灵活、支持可变高度）
- 配合 CSS columns 或自定义 masonry + 虚拟滚动
- 图片卡片高度预计算（从后端拿宽高，前端算准确位置）

### 骨架屏
- 首次加载显示 skeleton 占位（数量 = 视口可容纳卡片数 × 1.5）
- 数据到达后平滑替换，无布局跳动

## 理由

- 1w+ 张图，全渲染会有上万个 DOM 节点，滚动卡顿、内存爆炸
- 从第一天就考虑性能，不是后期再优化
- 配合三档缩略图，首屏加载快

## 备选
- `react-window` / `react-virtuoso` — 也可以，但 tanstack 生态更统一
- 分页加载（无限滚动）— 更简单但滚到底还是会累积 DOM，万级还是会卡
