# ADR 0002 — 相册无限嵌套 + 跨项目不互通 + 同项目多对多

**状态：Accepted** · 2026-08-08

## 背景

相册系统的三个核心问题：
1. 层级深度是固定还是无限？
2. 一个素材能否属于多个相册？
3. 顶层项目之间是否隔离？

## 决策

1. **相册支持无限嵌套**（自引用树 + path 字段加速后代查询）
2. **同一项目内，素材与相册多对多**：一个素材可以在多个相册里
3. **跨顶层项目（如"拍照原片"和"例图"）不互通**：素材只在所属项目内可见

## 理由

### 无限嵌套
- 实现成本和固定 3 层几乎一样（自引用表）
- 不限制用户未来的分类方式，比如"街拍→城市街拍→上海→外滩"可以无限细分

### 同项目多对多
- 用户有多个分类维度（场景/风格/服装），需要同时按不同维度组织
- 多对多比"文件夹+标签"更灵活，用户可以把同一张图放到不同维度的相册里
- 标签系统仍然存在，标签用于精细检索，相册用于用户主动的"收藏夹"式组织

### 跨项目不互通
- 顶层项目（如原片 vs 例图）是完全不同的用途，素材不会混
- 简单的项目隔离，避免误操作

## 后果

- 关联表 asset_albums 支持多对多
- 查询相册内素材时，要确保只返回该项目下的（防止跨项目泄露）
- 删除相册时只删关联，素材进"未分类"（Q5 决策）
- 前端相册树按项目根节点分组显示
