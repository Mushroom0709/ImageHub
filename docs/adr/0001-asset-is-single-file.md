# ADR 0001 — 素材以单文件为单位，同组关系通过标签表达

**状态：Accepted** · 2026-08-08

## 背景

从小红书/抖音采集的内容通常是多图笔记（一条笔记含 3-18 张图）。需要决定素材的最小单位是"单图"还是"整组笔记"。

## 决策

**素材 (Asset) = 单张图片 / 单个视频**。一条笔记的多张图各自独立为素材。

同组关系通过**来源标签**（`source_note_id`、`source_author`、`source_location` 等）表达，需要看同组时按标签筛选即可。

## 理由

1. **简单**：单文件为单位的模型最简单，表结构、API、前端都不需要处理"组内图片"的特殊逻辑
2. **灵活**：每张图可以独立打不同的标签（比如同一条笔记里，图1是全身照、图2是特写，标签不一样）
3. **标签已经够用**：用标签表达同组关系，比引入 Group 实体轻量得多，而且和现有的标签系统复用
4. **用户操作一致**：不管是单图还是采集来的多图，用户的操作方式（打标、移动相册、删除）都一样

## 备选方案

### 方案 B：组 (Group) 实体，组内多张图
- 优点：天然对应笔记概念，一键展示整组
- 缺点：组内单图能否独立打标？组和相册的关系？复杂度直接翻倍
- 否决原因：收益不大，标签完全能替代

### 方案 C：既有组又有单图，两种实体
- 缺点：两套模型，所有功能都要做两遍
- 否决原因：过度设计

## 后果

- 采集时，一条笔记拆成 N 个素材，每个素材打上相同的来源标签
- 需要看整组时，按 `source_note_id` 标签筛选
- 素材详情页可以展示"同笔记其他图片"（通过来源标签查询）
