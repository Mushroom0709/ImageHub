# ADR 0002 — 纯标签驱动，移除相册概念

**状态：Accepted** · 2026-08-08
**前身：** 原 ADR 0002 为"相册无限嵌套 + 多对多"，后因用户决策推翻，改为纯标签驱动。

## 背景

最初设计了"多级相册 + 标签"双轨系统。经过讨论，用户认为相册系统是多余的——既然已经有了丰富的多维度标签体系，所有的分类、浏览、筛选都可以通过标签树和标签组合来完成。

AI 主动构建和维护标签体系，采集进来的素材自动打标，用户通过标签树导航。相册这个中间层没有存在的必要。

## 决策

**移除相册 (Album) 概念，系统改为纯标签驱动 (tag-first)**。

- 导航方式：左侧为**标签分类树**（场景/风格/服装/妆容/姿势/构图/色调/身材修饰点 八大类，每类可无限层级展开）
- 组织方式：所有素材通过标签组织，无文件夹概念
- 浏览方式：点击标签 = 筛选该标签下所有素材；多选标签 = 交集筛选
- 收藏/分组需求：后续通过"集合 (Collection)"概念实现（类似收藏夹，但本质也是一组标签的快捷方式 + 手动增减）

## 保留的层级概念

- **标签本身支持无限层级**（如"场景→自然风光→山川地貌→雪山"）
- 标签的层级用于导航和浏览，不是相册

## 理由

1. **更简洁**：一套系统搞定所有分类，不需要"相册"和"标签"两套概念让用户选
2. **更灵活**：标签的多对多天然支持多维度分类，比相册的树状结构强大得多
3. **AI 友好**：AI 打标 = AI 归类，一步到位，不需要再额外决定放哪个相册
4. **符合实际使用**：找图的时候用户想的是"草原 + 连衣裙 + 氛围感"，而不是"我把它存在哪个文件夹了"

## 后果

- 移除 albums 表和 asset_albums 关联表
- 左侧导航从相册树改为标签分类树
- "未分类"概念改为"未打标"（没有任何标签的素材）
- 后续如果需要收藏夹/精选集功能，用 Collection（集合）实现，而不是相册
- ADR 0003（删除策略）中的"删除相册"部分作废，只保留素材软删
