# ADR 0005 — 视频处理策略：抽封面 + 双模式播放

**状态：Accepted** · 2026-08-08

## 背景

系统中有视频素材（采集自抖音/小红书，或用户上传）。需要决定视频的处理方式和前端播放体验。

## 决策

**视频处理：**
- MVP 只做**自动抽封面帧**（第 1 秒或关键帧），存在 OBS 公共桶
- 不做转码、不做多清晰度、不抽多帧（后期再加）

**播放体验（双模式）：**
1. **瀑布流模式**：视频滚动到可视区域时**自动静音播放**（类似小红书/微博），鼠标悬停或点击进入详情
2. **沉浸式模式**：全屏上下滑动一个接一个播放（类似抖音/TikTok），支持点赞、标签查看

## 理由

- 双模式覆盖两种使用场景：快速浏览找灵感（瀑布流）+ 沉浸式看姿势细节（全屏流）
- MVP 不做转码，节省存储和算力，原文件直接播
- 封面帧用于瀑布流中视频未播放时的展示

## 后果

- assets 表增加 `duration`（时长）、`has_audio`（有无声音）字段
- OBS 存储视频原文件 + 封面图
- 前端需要两套播放器组件：瀑布流内联播放器、全屏沉浸式播放器
- 大视频文件可能加载慢，后续需要转码时再补 ADR
